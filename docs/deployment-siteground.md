# SiteGround deployment

## Directory layout

The deployed subdomain directory must contain:

```text
syncbridge.psdt.pro/
├── .env
├── app/
├── bin/
├── bootstrap.php
├── resources/
├── storage/
└── public_html/
    ├── .htaccess
    ├── assets/
    └── index.php
```

Only `public_html` is exposed by the web server. `.env`, application code and
the worker scripts stay above the document root.

## Environment file

Copy `.env.example` to `.env` and replace every placeholder. Use the exact
database and user names generated by SiteGround. Do not add spaces around `=`.
Each of `APP_KEY`, `WEBHOOK_SECRET` and `CRON_TOKEN` must be a different random
secret containing at least 32 characters.

Never commit or place `.env` inside `public_html`.

## Database

Import `database/schema.sql` once into the selected database. The import is
idempotent only for table creation; it does not modify an existing schema.

## Permissions

Recommended starting permissions:

- directories: `0755`;
- PHP, CSS, JS and configuration files: `0644`;
- `.env`: `0600` when supported by the hosting account.

## Verification order

1. Open `/health`; expect `{"status":"ok","database":"connected"}`.
2. Open `/`; expect an empty dashboard without errors.
3. Submit a successful order event.
4. Submit a temporary failure and run two manual retries.
5. Submit a permanent failure and replay it.
6. Confirm the five MySQL tables contain the expected records.

## Scheduled tasks

Configure the hosting cron manager only after the interactive verification:

- run `bin/worker.php` every minute;
- run `bin/cleanup.php` once per day.

Use the PHP executable and absolute paths displayed by the hosting panel. Do
not guess them. The HTTP worker endpoint is an alternative when CLI cron is not
available and requires the `X-SyncBridge-Cron-Token` header.
